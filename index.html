01 / One project, clear boundaries

一个项目，两类内容，
一组可定位关联源。

不是把所有东西塞进同一个本地目录，而是保留每种工作的原有习惯，再按项目规约映射到统一仓库。

01
项目资料

合同、报价、方案、交付物，以及团队按文件夹整理的业务材料。

02
项目知识

Obsidian 项目目录中的背景、决策、会议记录与长期知识。

03
关联源

代码仓库、飞书、Figma、网站或本机目录保留在原系统，只登记可移植入口。

02 / Current product

同步只是底层能力。
上层是项目记忆。

FileShare 不要求团队学习提交、分支和合并。它把需要判断的变化显性化，把机械的版本管理留在后台。

01

多项目工作区

每个项目独立绑定 GitHub 仓库、项目资料和项目知识；左侧栏快速切换，不混用同步状态与历史记录。

02

自动同步与冲突保护

文件变化自动形成版本并同步。发现冲突就暂停并保留双方内容，不会为了“同步成功”静默覆盖。

03

可读的项目动态

规则引擎把一次文件更新整理成业务变化、工程影响与风险提示；固定规则运行时不消耗 AI Token。

04

云端文件与版本浏览

在桌面端直接查看 GitHub 当前文件、目录和历史版本，明确区分本地工作副本与云端生效版本。

05

四个项目规则文件

README、AGENTS、PROJECT.yaml 与 CONTEXT_INDEX 跟随仓库同步，让本地和云端 Agent 使用同一份入口与边界。

03 / Share with an Agent

分享一个项目，不再先写安装手册。

每个项目都能生成一段专属提示词。把它交给同事正在使用的 Agent，Agent 会下载官方版本并绑定准确仓库；登录、授权与本地目录仍由成员本人确认。

  1. 固定官方域名、版本文件与 SHA-256 校验流程。
  2. 绑定当前项目仓库，不复用分享者的本地路径。
  3. 分别选择新的项目资料和项目知识空目录。
  4. 根据 PROJECT.yaml 为当前设备绑定需要的关联源。
  5. 遇到登录、授权、覆盖或合并风险时停下来交给人。

04 / Clear boundaries

项目可以统一，
边界必须清楚。

FileShare 把安全行为做成默认规则，而不是藏在设置深处。需要人判断的地方会停下来，不替用户做不可逆决定。

✓
文件在团队自己的 GitHub

桌面端直接连接已授权仓库；FileShare 不要求把项目文件先上传到另一套云存储。

✓
凭据进入 macOS 钥匙串

GitHub 授权信息使用系统安全存储；项目分享提示词不包含密码、Token、本地路径或文件内容。

✓
关联源不复制、不接管

代码、飞书和设计稿仍由原系统管理；FileShare 只同步导航信息，不制造第二套工程历史或权限体系。

✓
敏感证据默认隐藏

活动记录可以提示风险与类别，但不会在界面中直接展示凭据、身份材料和其他严格敏感内容。

05 / FAQ

开始之前，先把工作方式说清楚。

01团队成员需要会 Git 吗？

不需要。成员只需连接 GitHub 仓库、选择项目资料与项目知识目录并开启自动同步。提交、拉取和安全版本由 FileShare 在后台处理。

02为什么要分别选择两个目录？

项目资料对应人类按文件夹整理的业务材料，项目知识对应可由 Obsidian 直接打开的 Markdown 项目目录。两者用途和协作方式不同，但都会进入同一份项目上下文。

03分享项目时会暴露我的本地路径吗？

不会。分享提示词只包含官方下载安装流程、当前 GitHub 仓库、可移植的关联源地址和安全步骤。新成员在自己的电脑上重新选择两个目录并单独绑定本机来源。

04代码会不会和原模块仓库冲突？

不会。代码仓库作为关联源保留在原 Git 工作流中，FileShare 不复制代码、不执行工程提交，只通过 PROJECT.yaml 帮助人和 Agent 定位。

05当前支持哪些平台？

当前正式发布 Apple 芯片 Mac 版本，安装包经过 Developer ID 签名和 Apple 公证。其他平台会在完成同等级别的安装与同步验收后发布。
